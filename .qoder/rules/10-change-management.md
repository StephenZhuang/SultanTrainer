# 文档驱动变更管理

本项目采用文档驱动开发：文档是唯一需求来源，代码是文档的实现。

## 变更流程

```
需求确认 → 更新 docs/ 文档 → 用户确认文档 → 编写/修改代码 → 回写文档（如有偏差）
```

1. **需求确认**：与用户讨论需求，澄清细节，等用户确认
2. **文档先行**：先更新 docs/ 中对应的设计文档或数据结构文档
3. **用户审阅**：展示文档变更，等用户确认后再动代码
4. **代码实施**：按确认后的文档编写代码
5. **回写检查**：如实施中发现文档与实际不一致，回写文档

## AI 行为约束

- **问方案只给方案**：用户问"怎么做"时只说明方案，不直接实施，等用户说"做"/"改"/"实施"再动手
- **禁止顺手重构**：只做被要求的变更，不重构无关代码、不优化无关逻辑
- **改动前说明影响**：每次修改前列出涉及的文件、影响范围、潜在风险
- **不猜测需求**：需求不明确时主动提问，不做假设性实现

## 分支策略

- `main` — 稳定版本
- `develop` — 开发主线
- `feature/xxx` — 功能分支

## Commit 规范

使用 Conventional Commits：

```
feat: 新增卡牌管理功能
fix: 修复计数器保存后数值溢出
docs: 更新存档结构文档中仪式系统章节
refactor: 重构 SaveManager 备份逻辑
chore: 更新 build.sh 构建配置
```
