# 文档维护规范

## 文档目录结构

```
docs/
├── save-data-structure.md              # 游戏存档数据结构（逆向分析）
└── superpowers/specs/
    └── 2026-10-10-sultan-trainer-design.md  # 设计文档
```

## 文档类型

| 文档 | 内容 | 更新时机 |
|------|------|----------|
| 设计文档 | 功能需求、架构、UI 设计 | 新增功能、变更设计时 |
| 数据结构文档 | 存档格式、字段含义、配置文件 | 发现新字段、游戏更新时 |

## 编写原则

- **只描述 what，不描述 how**：文档记录需求和行为，不包含实现细节（依赖注入、具体算法等留在代码中）
- **以实际数据为准**：数据结构文档必须基于真实存档分析，不猜测字段含义
- **标注来源**：字段说明标注来自哪个配置文件或存档文件

## 文档同步

- 代码实现与设计文档不一致时，以文档为准，更新代码
- 实施中发现文档遗漏或错误，先更新文档再继续实施
- 游戏更新后重新分析存档，更新数据结构文档
